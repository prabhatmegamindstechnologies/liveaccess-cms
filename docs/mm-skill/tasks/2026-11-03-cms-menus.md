# CMS: Menus section (header + footer links)

- Flow: FEATURE
- Status: done (not committed)
- Requested: 2026-11-03, Prabhat ("lets implement the menus tabs and its functionality", prototype screenshot)
- Branch: feature/cms

## Request
Build `/la-studio/menus`: edit the header and footer menu links (label, link, order, add, remove),
like the "Menus" screen in the admin prototype.

## What exists today (checked 2026-11-03)
- `menus` table already in the schema (`location` unique, `items` jsonb), empty.
- 29 HTML pages. Footer is identical on all 29. Header is identical on 25; 4 differ (to check: likely the
  active-link marker or a page-specific button).
- Header: How it works, Features, About, Contact + "Get the app" button.
- Footer: Product (How it works, Features, Get the app), Resources (Troubleshooting guides, Process areas),
  Company (About, FAQ, Contact, Privacy Policy, Terms & Conditions).
- Every page's HTML is stored in `pages` / `articles` (`html` draft, `published_html` live).
- Publish centre (Day 4) is not built yet.

The 4 header differences are only `aria-current="page"` on the page's own link (about, contact, features,
how-it-works). The footer's Company column ends with a "Cookie settings" button (not a link).

## Brainstorm (answers 2026-11-03, Prabhat)
1. Editable: header 4 links + "Get the app" button label and link; footer Product / Resources / Company links
   + the 3 column headings. → **both**
2. Menu changes are saved as a **draft only**; the Publish centre (later) applies them to all pages.
3. Links: **dropdown of the site's own pages + "External link"** (full `https://` address only).
4. Limits: max 6 header links, 8 links per footer column, labels max 30 characters (proposed; not objected to).
5. **Save button** (no auto-save).

## Plan
- [x] 1. **Shared menu code** `packages/shared/src/menus.ts` (tests first):
      - `readMenus(html)`: header links, button (label + link), footer columns (heading + links) from a page.
      - `applyMenus(html, menus, pageFile)`: writes them back into a page's header and footer only. Keeps the
        button's phone icon, the logo, the mobile menu button, the footer intro, copyright and the
        "Cookie settings" button. Sets `aria-current="page"` on the link to the page itself, like today.
      - Test: on all 29 real pages, `applyMenus(page, readMenus(page))` gives back the page unchanged
        (so the layout lock holds), and a changed label/link/order lands in the right place.
      - `validateMenus()`: limits above, labels plain text 1–30 chars, link = a known site page or `https://…`.
- [x] 2. **Database**: migration `0002` adds `version`, `updated_at`, `updated_by` to `menus`. One row
      (`location = 'site'`) holds the draft. First open with an empty table → read from the home page's live HTML.

      - `GET /` → draft menus, version, last edited by/at, and the list of site pages for the dropdown.
      - `PUT /` `{ baseVersion, menus }` → validated, saved; 409 "changed by X" if someone saved first; 422 on
