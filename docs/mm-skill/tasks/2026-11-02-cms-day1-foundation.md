## Guard rail: don't deploy CMS files over FTP
`deploy.yml` copies `*.html *.css *.js *.png *.svg *.mp4 *.txt *.xml *.woff2` **from the repo root** to the live
server. So on Day 1 **no new files with those extensions go in the repo root**. Root-level additions are limited to:
`package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `tsconfig.base.json`, `docker-compose.yml`, `.env.example`,
`.nvmrc`, `.gitignore` changes. Everything else lives under `cms/`, `packages/`, `site/`. Existing root files are not
edited.

## Auth (Day 1 scope)
- `POST /la-studio/api/auth/login` — email + password. Generic "Email or password is wrong" for every failure.
  5 wrong tries → `locked_until = now + 15 min`. Success resets the counter.
- Session: 32 random bytes in an httpOnly, Secure (in prod), SameSite=Strict cookie `la_session`, path `/la-studio`.
  DB stores only the sha256 of the token. 8-hour idle timeout, renewed on use.
- `GET /la-studio/api/auth/me` — current user + CSRF token. `POST /la-studio/api/auth/logout` — needs the
  `X-CSRF-Token` header; deletes the session.
- Passwords: argon2id, minimum 12 characters.
- Every login, failed login, lockout and logout → `audit_log`.
- Out of Day 1 (Day 6): IP rate limits, role middleware on content routes.

## Site import (`pnpm import:site`)
- Reads the root HTML files directly (`SITE_ROOT=..`), no changes to them.
- **Pages (12):** index, about, contact, features, how-it-works, faq, privacy-policy, terms-and-condition,
  delete-account, get-app, guides, process-areas. Stores the **raw file HTML** (scripts, GA4 tag, consent script
  included — the admin preview strips scripts at view time, the build will write this HTML back). SEO fields read from
  `<title>`, meta description, canonical.
- **Guides (6) / areas (8):** title (`h1`), slug (file name without `guide-` / `area-` and `.html`), summary (`.lede`),
  area (byline link, guides only), published date (`<time datetime>`), blocks (via `importBlocks` from the article),
  SEO from the head. Status `published`.
- Idempotent: running it again updates the same rows (upsert on key / (type, slug)); writes one revision per row.
- Prints a summary; fails loudly if a count is not 12 / 6 / 8.
- HTML parsing in Node: `linkedom` (DOM API compatible with the prototype code). I'm going from memory on its API —
  verify on install.

## Tests (written first — TDD)

   → 403, with CSRF → 204 and the session is gone; expired session → 401.

   page still contains `G-JFHJD3T51M`; Evaporator fouling guide has 12 blocks with a `safety` callout first; re-running
   the import doesn't create duplicates.

## Rejected alternatives
- **Moving pages into `site/templates/` today** — would break the FTP deploy on the next merge to `main`.
- **Neon cloud for local dev** — no account yet; Docker gives the same PostgreSQL 16 and needs nothing external.
- **`argon2` (native, node-gyp)** vs **`@node-rs/argon2`** (prebuilt binaries) — picking `@node-rs/argon2` so it
  installs on Windows and Vercel without a compiler. From memory; verify.
- **Prisma** — heavier in serverless functions; plan v3 uses Drizzle.
- **JWT in localStorage** — readable by scripts; httpOnly cookie session is safer.

## Security Gate
Status: PASSED (after fixes)
Independent review by the security-auditor agent found 2 blocking issues and 7 warnings; all fixed except as noted.
Findings:
- ✅ B1 fixed: parallel wrong passwords could skip the lockout (read-modify-write). Now an atomic
  `failed_logins = failed_logins + 1` and a conditional lock. Test "still locks the account when 10 wrong passwords
  arrive at the same time" failed before the fix, passes now.
- ✅ B2 fixed: locked/disabled/unknown accounts answered faster than wrong passwords (email enumeration by timing).
  Now exactly one argon2 check runs on every login attempt, before any branch.
- ✅ W2 fixed: `//host` and `/\host` links refused; only `target="_blank"`, always with `rel="noopener noreferrer"`;
  nesting deeper than 200 tags is reduced to text before parsing (linkedom itself overflowed at 5,000 levels).
- ✅ W3 fixed: 64 KB body limit (`hono/body-limit`); Day 3 raises it on the upload route only.
- ✅ W4 fixed: login requires `application/json` (415 otherwise); every POST/PUT/PATCH/DELETE refuses
  `Sec-Fetch-Site: cross-site` and a foreign `Origin` (403).
- ✅ W5 fixed: cookie is `Secure` by default; local dev opts out with `CMS_INSECURE_COOKIES=1` in `.env`.
- ✅ W6 fixed: unknown-email audit entries store a 16-char sha256 fingerprint, not the typed text.
- ✅ W7 fixed: Docker PostgreSQL bound to `127.0.0.1:5433`.
- ✅ W1 partly fixed: `client-ip.ts` uses `x-real-ip` only when `VERCEL=1`/`TRUST_PROXY=1`, else the socket address;
  `x-forwarded-host` likewise only behind a trusted proxy. Re-check on Vercel (Day 6).
- ✅ CSRF comparison is constant-time (`timingSafeEqual`).
- ✅ No hardcoded secrets (grep), `.env` ignored, seed password typed at runtime.
- ✅ `pnpm audit`: no high/critical.
- 🟡 esbuild ≤0.24.2 moderate advisory (GHSA-67mh-4wv8-2f99) via `drizzle-kit` → `@esbuild-kit/*`. Dev-only; the
  esbuild dev server is never run. Revisit when drizzle-kit drops `@esbuild-kit`.
- 🟡 Per-account lockout lets anyone who knows the admin email keep it locked. Add per-IP limits on Day 6.
- 🟡 Machine-wide npm/pnpm install cooldown not configured (project has `minimumReleaseAge: 10080`). Suggest `/npm-protect`.
- Note: the sanitizer turns `rel="noopener"` on external links into `rel="noopener noreferrer"` when an editor saves
  a field; outbound links then send no Referer (pages imported as-is are not affected).
